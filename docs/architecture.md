# MiniVM16 Architecture

## 1. Program Flow

The program expects to be called with the name of a file (or the path to the desired file). Upon execution, the file is read and its contents are copied to `assembler.source`.

Once the file is stored in `assembler.source`, `encode()` can be called.

## 2. Assembler

The `encode()` function starts the assembler's process of creating the Y86 machine code. The machine code is generated sequentially, starting with the lexer.

The lexer reads through the source file and generates lexical tokens. The tokens hold basic information such as type and value (or data in the case of labels) in order to be syntactically analyzed next.

The parser uses the generated tokens in order to produce statements. The syntactic analysis is done at this stage together with the semantic analysis.

The statements are then used in the final step of encoding: resolving the label addresses and generating the bytecode for the Y86 simulated machine.

The bytecode is not yet transferred to the memory of the VM, as this is going to be done by the `loadMemory()` function. The bytecode remains stored in the `ByteBuffer`.

## 3. VM

The VM has 64 KiB of byte-addressable memory. The stack pointer register has to be initialized by the program writer in the case of using `PUSHW`, `POPW`, `CALL` or `RET`.

The VM's processor executes the bytecode generated by the assembler. In order to see the results, you can use the debug function `debug_dump_all()`, which prints the CPU's number of executed steps and changes in the registers and memory.

The function `run_vm()` controls execution until the CPU status is no longer `CPU_AOK`.

## 4. Memory

All accesses to the MiniVM memory are done through the read and write functions that directly use the virtual memory.

Word accesses are performed using the little-endian format. The functions check whether the read or write is possible at the moment.

A word write at address `0xFFFF` will generate an `m_invalid` memory status, which will then modify the CPU's status and stop the machine.

## 5. CPU

The CPU executes steps. Each step consists of six stages:

`Fetch → Decode → Execute → Memory → Write Back → PC Update`

### 5.1 Fetch

In the fetch stage, memory is read using the current program counter, and the registers, as well as `ifun` and `icode`, are determined.

**Implementation:**

Fetch firstly reads one byte from `[PC]`. It identifies `icode` and `ifun` with the convention that each of the two has four bits.

Based on `icode` and `ifun` it determines the instruction size which is used to calculate `valP`. For some instructions this is the only step.

`valP` is the next value of PC if there are no control flow instructions used or their condition is not satisfied.

The second step may be reading the second byte and identifying `rA` and `rB`. If there is the case, fetch will read two more bytes that encode a two byte value (the second step will occur only for the instructions that need it). This value will be stored in `valC`.

Fetch also verifies if `ifun` is valid and returns a `CPU_INS` error if that is the case. If the memory access can't be fully done it will return `CPU_ADDR`.

### 5.2 Decode

Determines which registers are used and extracts their values.

**Implementation:**

`srcA` and `srcB` are used to emulate a register file. `srcA` will take `rA`'s value and `srcB` will take `rB`'s for some instructions.

By value we mean the identification value, as the value that is inside the registers is copied into `valA` for `srcA` and `valB` for `srcB`.

For instructions `RET` and `POPW`, `srcA` is `RSP`. For instructions `CALL`, `PUSHW`, `RET` and `POPW`, `srcB` is `RSP`.

For some instructions `valA` or `valB` may be zero if `rA` or `rB` is `NO_REG`.

### 5.3 Execute

Computes the values that would be computed by the ALU in a real processor and updates the CPU's flags (it also computes addresses).

**Implementation:**

It uses `valA` and `valB` in order to compute `valE`. `valE` represents the value that needs to be computed by the instruction.

For the instructions that use the stack `valE` is equal to `RSP` minus or plus two.

In the case of `OPW` it specifically uses a function made to simulate the ALU and may change the CPU's flags.

`valE` may also represent an address in the case of memory access instructions or an immediate.

### 5.4 Memory

Accesses memory and reads from or writes to it depending on the instruction.

**Implementation:**

It uses the potentially computed memory addresses from the before stage or `valA` and reads the memory or writes in it.

If the memory is read the result from the reading will be stored in `valM` for the next stages.

### 5.5 Write Back

Writes the computed or memory-read value to the destination register.

**Implementation:**

Depending on the instruction `valE` or `valM` is written to the destination register.

In the case of conditional moves the instruction will be executed only if the condition is satisfied.

In the case of `POPW`, `valM` contains the value read from the top of the stack, while `valE` contains the incremented stack pointer. Both values are written to their corresponding registers during Write Back.

### 5.6 Program Counter Update

Updates the program counter with the address of the next instruction (the updated value may come from a jump or memory).

**Implementation:**

The PC will be updated based on the instruction.

For `RET`, PC will be updated to `valM`. For `CALL` and `JXX` it will be updated to `valC`, but in the case of `JXX` only if the condition is satisfied.

In the rest of the cases PC will be updated to `valP`.
